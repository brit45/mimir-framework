# T5 pour Lumen

Le registre `t5` fournit un encodeur T5 natif Mímir : attention bidirectionnelle
sans facteur de mise à l’échelle, biais de position relatifs par buckets partagés
entre les blocs, RMSNorm sans biais, FFN ReLU, masque de padding et embeddings
liés à la tête de préentraînement. Aucune dépendance à PyTorch.

Il s’agit de l’encodeur et d’une tête de débruitage par tokens. Le décodeur
text-to-text autorégressif et l’import de poids Hugging Face ne sont pas fournis.
Le préentraînement masque un segment contigu et calcule la cross-entropie
uniquement sur les positions masquées ; ce n’est pas l’objectif original T5
avec séquence cible de sentinelles et décodeur.

## Entraînement

Fournir un corpus UTF-8, puis :

```sh
./run_mimir.sh --lua scripts/training/train_t5.lua -- \
  --corpus /chemin/corpus.txt --steps 10000 --seq-len 77 \
  --checkpoint-dir checkpoint/t5
```

La configuration par défaut est `configs/t5.json`. Le tokenizer est créé à
partir du corpus, ou chargé depuis `--tokenizer /chemin/tokenizer.json`.
Les paramètres de corruption `training.mask_ratio` (0.15) et `training.mask_id`
(dernier ID du vocabulaire par défaut) se règlent dans la configuration.
Les checkpoints RawFolder contiennent les poids, l’optimiseur et le tokenizer.
Le checkpoint de fin est écrit dans `<checkpoint-dir>/final` (donc
`checkpoint/t5/final` avec le défaut). Le script fourni initialise un nouveau
modèle à chaque lancement ; il ne propose pas de reprise d’optimiseur, malgré
la présence de cet état dans ses checkpoints.

## Conditionnement de Lumen

```sh
./run_mimir.sh --lua scripts/training/train_lumen_diffusion.lua -- \
  --text-conditioning t5 --text-t5-checkpoint checkpoint/t5/final \
  --vae-checkpoint /chemin/vae_conv --dataset /chemin/images
```

Les autres options restent celles du script Lumen. Celui-ci reprend le tokenizer
et la longueur de séquence du checkpoint T5. L’encodeur est gelé ; une projection
vers `hidden_size` est entraînée avec le diffuseur. Dans ce chemin, les prompts
sont paddés ou tronqués à `seq_len`. Le chemin Transformer interne conserve son
fonctionnement dynamique existant. T5 et VAEText sont mutuellement exclusifs.

Pour utiliser uniquement l’encodeur via le registre, passer `encoder_only=true` :
l’entrée nommée est `text_ids` et la sortie est `[seq_len, d_model]`, sinon `[seq_len, vocab_size]`.

## Tests

```sh
MIMIR_RUNTIME=cpu OMP_NUM_THREADS=1 ./run_mimir.sh --lua scripts/tests/test_t5.lua
MIMIR_RUNTIME=cpu OMP_NUM_THREADS=1 ctest --test-dir build --output-on-failure \
  -R '^(ModelTest.T5|LuaTest.T5)$'
```

Le test natif vérifie aussi le gradient des biais relatifs par différences finies,
le chargement dans Lumen et la conservation des poids gelés après optimisation.
Le test complet entraînement/reprise/génération se lance avec
`python3 scripts/tests/test_lumen_t5.py`.
Référence architecturale : https://huggingface.co/docs/transformers/model_doc/t5
